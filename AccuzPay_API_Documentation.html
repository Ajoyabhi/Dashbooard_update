Introduction

Use AccuzPay APIs to create payin and payout transactions and to track their status. This guide covers authentication, endpoints, request/response formats, and best practices for integrating with our payment gateway.

AccuzPay provides a comprehensive payment gateway solution that allows you to:

  • Accept payments from customers (Payin)
  • Transfer money to beneficiaries (Payout)
  • Track transaction status in real-time
  • Monitor account balances and transaction limits

Base URL

All API endpoints are hosted at:

https://dashboard.accuzpay.in

Authentication

All API requests require authentication using JWT tokens. Include the token in the Authorization header of your requests.

Header Format

Authorization: YOUR_JWT_TOKEN

Example

curl --location 'https://dashboard.accuzpay.in/api/payments/payin' \
--header 'Content-Type: application/json' \
--header 'Authorization: YOUR_JWT_TOKEN' \
--data '{...}'
Note: Get your JWT token from the Developer Settings section in your dashboard.

Create Payin Transaction

Create a new payin transaction to accept payments from customers.

Endpoint

POST https://dashboard.accuzpay.in/api/payments/payin

Request Body

{
  "order_amount": 1000,
  "name": "John Doe",
  "email": "john@example.com",
  "phone": "9876543210",
  "reference_id": "TXN123456"
}

Parameters

Parameter Type Required Description
order_amount number Yes Amount to be charged (in paise)
name string Yes Customer's full name
email string Yes Customer's email address
phone string Yes Customer's phone number (10 digits)
reference_id string Yes Unique reference ID (12-25 alphanumeric characters)

cURL Example

curl --location 'https://dashboard.accuzpay.in/api/payments/payin' \
--header 'Content-Type: application/json' \
--header 'Authorization: YOUR_JWT_TOKEN' \
--data '{
  "order_amount": 1000,
  "name": "John Doe",
  "email": "john@example.com",
  "phone": "9876543210",
  "reference_id": "TXN123456"
}'

Response Example

{
  "success": true,
  "data": {
    "transaction_id": "TXN_123456789",
    "payment_url": "https://dashboard.accuzpay.in/pay/TXN_123456789",
    "status": "pending",
    "amount": 1000,
    "reference_id": "TXN123456"
  }
}

Create Payout Transaction

Create a new payout transaction to transfer money to beneficiaries.

Endpoint

POST https://dashboard.accuzpay.in/api/payments/payout/

Request Body

{
  "amount": 500,
  "beneficiary_name": "Jane Smith",
  "account_number": "1234567890",
  "ifsc_code": "SBIN0001234",
  "reference_id": "PAYOUT123456"
}

Parameters

Parameter Type Required Description
amount number Yes Amount to be transferred (in paise)
beneficiary_name string Yes Beneficiary's full name
account_number string Yes Beneficiary's bank account number
ifsc_code string Yes Bank's IFSC code
reference_id string Yes Unique reference ID (12-25 alphanumeric characters)

cURL Example

curl --location 'https://dashboard.accuzpay.in/api/payments/payout/' \
--header 'Content-Type: application/json' \
--header 'Authorization: YOUR_JWT_TOKEN' \
--data '{
  "amount": 500,
  "beneficiary_name": "Jane Smith",
  "account_number": "1234567890",
  "ifsc_code": "SBIN0001234",
  "reference_id": "PAYOUT123456"
}'

Response Example

{
  "success": true,
  "data": {
    "transaction_id": "PAYOUT_123456789",
    "status": "processing",
    "amount": 500,
    "reference_id": "PAYOUT123456",
    "estimated_completion": "2024-01-15T10:30:00Z"
  }
}

Check Transaction Status

Check the status of payin and payout transactions using their transaction IDs.

Payin Status

Endpoint

GET https://dashboard.accuzpay.in/api/payments/payin/transaction/{transaction_id}

cURL Example

curl --location 'https://dashboard.accuzpay.in/api/payments/payin/transaction/TXN_123456789' \
--header 'Authorization: YOUR_JWT_TOKEN'

Response Example

{
  "success": true,
  "data": {
    "transaction_id": "TXN_123456789",
    "status": "completed",
    "amount": 1000,
    "reference_id": "TXN123456",
    "payment_method": "UPI",
    "created_at": "2024-01-15T09:00:00Z",
    "completed_at": "2024-01-15T09:05:00Z"
  }
}

Payout Status

Endpoint

GET https://dashboard.accuzpay.in/api/payments/payout/transaction/{transaction_id}

cURL Example

curl --location 'https://dashboard.accuzpay.in/api/payments/payout/transaction/PAYOUT_123456789' \
--header 'Authorization: YOUR_JWT_TOKEN'

Response Example

{
  "success": true,
  "data": {
    "transaction_id": "PAYOUT_123456789",
    "status": "completed",
    "amount": 500,
    "reference_id": "PAYOUT123456",
    "beneficiary_name": "Jane Smith",
    "account_number": "1234567890",
    "ifsc_code": "SBIN0001234",
    "created_at": "2024-01-15T09:00:00Z",
    "completed_at": "2024-01-15T10:30:00Z"
  }
}

Transaction Status Values

  • pending - Transaction is being processed
  • processing - Transaction is in progress
  • completed - Transaction completed successfully
  • failed - Transaction failed
  • cancelled - Transaction was cancelled

Check Account Balance

Check your current account balance and transaction limits.

Endpoint

GET https://dashboard.accuzpay.in/api/payments/balanceCheck

cURL Example

curl --location 'https://dashboard.accuzpay.in/api/payments/balanceCheck' \
--header 'Authorization: YOUR_JWT_TOKEN'

Response Example

{
  "success": true,
  "data": {
    "wallet_balance": 50000,
    "settlement_balance": 25000,
    "daily_limit": 100000,
    "monthly_limit": 1000000,
    "used_daily": 15000,
    "used_monthly": 75000
  }
}

Notes & Requirements

Important Guidelines

1. Reference ID Requirements

  • reference_id must be a unique alphanumeric string
  • Length should be between 12 to 25 characters
  • Must be unique across all your transactions

2. Data Format Requirements

  • Amounts should be provided as numbers (in paise)
  • Phone numbers must be exactly 10 digits
  • Email addresses should be valid format

3. Request Headers

  • Always include Content-Type: application/json for POST requests
  • Include Authorization: YOUR_JWT_TOKEN in all requests

4. Authentication

  • Get your JWT token from Developer Settings in your dashboard
  • Keep your token secure and don't share it publicly
  • Tokens may expire and need to be refreshed

5. Rate Limits

  • API calls are rate limited to prevent abuse
  • Contact support if you need higher limits

Error Handling

Common Error Responses

400 Bad Request

{
  "success": false,
  "error": "Invalid request parameters",
  "details": "Phone number must be exactly 10 digits"
}

401 Unauthorized

{
  "success": false,
  "error": "Unauthorized",
  "details": "Invalid or expired JWT token"
}

403 Forbidden

{
  "success": false,
  "error": "Forbidden",
  "details": "Insufficient balance for transaction"
}

404 Not Found

{
  "success": false,
  "error": "Not Found",
  "details": "Transaction not found"
}

500 Internal Server Error

{
  "success": false,
  "error": "Internal Server Error",
  "details": "An unexpected error occurred"
}

Error Handling Best Practices

  1. Always check the success field in responses
  2. Handle different HTTP status codes appropriately
  3. Implement retry logic for transient errors
  4. Log errors for debugging purposes
  5. Display user-friendly error messages

Best Practices

Security

  1. Never expose your JWT token in client-side code
  2. Use HTTPS for all API communications
  3. Validate all inputs before sending requests
  4. Implement proper error handling to avoid exposing sensitive information

Performance

  1. Cache responses when appropriate
  2. Implement pagination for large data sets
  3. Use webhooks for real-time updates instead of polling
  4. Batch requests when possible

Integration

  1. Test thoroughly in sandbox environment before going live
  2. Implement idempotency for critical operations
  3. Use webhooks for transaction status updates
  4. Keep transaction records for reconciliation

Monitoring

  1. Monitor API response times and error rates
  2. Set up alerts for failed transactions
  3. Track transaction volumes and patterns
  4. Regular reconciliation of transactions
